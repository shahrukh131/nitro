# NITRO — scroll-driven energy drink landing page

Frontend assessment. Code quality, architecture and detail are judged as much as visuals.
Design source: Figma `ATbjoNJohvEAdmKZ3GzwPs` — frames `1:2` Hero, `1:48` Story, `1:150` Products
(desktop 1920×1098). Ignore `1:248`. Figma is desktop-only; tablet/mobile are our own adaptation.

## Stack (fixed — do not add alternatives)

- Vite + React + TypeScript (`strict`, no `any`)
- Tailwind CSS v4 via `@tailwindcss/vite`
- gsap + ScrollTrigger + SplitText, `@gsap/react` (`useGSAP`)
- lenis (desktop + tablet only, driven by `gsap.ticker`, synced with ScrollTrigger)
- Mobile carousel: CSS scroll-snap
- NOT allowed: Framer Motion, Three.js, UI kits
- Extras: `vite-imagetools`, `sharp` (dev, label tint pre-render), `@fontsource` Outfit,
  Prettier + `eslint-config-prettier`

## Commands

- `npm run dev` / `npm run build` / `npm run preview`
- `npm run lint` — must pass with zero warnings
- `npx tsc -b` — must pass with zero errors

## Process

Build in stages and stop after each to show the result. **Never run `git commit`** — the user
commits. Suggest a conventional commit message (`feat:`, `fix:`, `chore:`, `refactor:`, `docs:`,
`perf:`) instead:

- a. Static, fully responsive layout (no animation)
- b. Can component with spin and shine
- c. Desktop timeline 1 → 2 → 3 with snap
- d. Tablet + mobile timelines, mobile menu, carousel
- e. Reveals, loading state, reduced motion, performance pass

├── lib/          cx.ts (class join), format.ts (price)

### Layout ↔ animation contract

- `--can-h` (CSS var per breakpoint) = height of the upright centre product can. Hero/story sizes are
  `--can-h × --can-scale-hero|story`; side cans `× --can-scale-md|sm`.
- Each section renders a `CanSlot` (`data-can-slot="hero|story"`) holding a static can. The static
  layout is the no-motion / reduced-motion experience; the timeline measures slots to place the
  fixed can, so layout tweaks never require touching timeline numbers.
- `short:` = landscape with height ≤ 500px (landscape phones): hero hides copy + socials, sizes cap by svh.
- Rotated slots: can is upright by default; `rotate-90` lays it on its side with the top to the right.

### Rules

1. Components only render markup and expose refs. All timeline logic lives in `animations/`.
2. One master can timeline, built in `App.tsx` with `useGSAP` + scope ref, using `gsap.matchMedia()`
   with a separate tuned timeline per breakpoint.
3. Never drive animation through React state — refs + GSAP only.
4. Products render from `data/products.ts`; no repeated hard-coded markup.
5. Motion values are relative (functions of `innerWidth`/`innerHeight`, or `xPercent`/`yPercent`)
   with `invalidateOnRefresh: true`.
6. Design tokens are CSS variables used through Tailwind (`@theme`). No hex values in components.
7. Animate only `transform` and `opacity`. Clean up ScrollTrigger on unmount/resize.
8. Comments only where the motion maths isn't obvious.

## Fake-3D can

- Natively **upright**, aspect width/height = 0.379. Size by height (H) with fixed aspect ratio.
- Layers: rounded clip (`overflow: hidden`) → can body image → wide label (4.32 × can width,
  color-burn blend, masked to can) → shine gradient → shadow ellipse.
- Spin = moving the label horizontally (`xPercent`) inside the clip.
- The Figma label's 3 panels are NOT identical, so `tint-labels` tiles the middle panel 3× →
  strip repeats every `LABEL_PERIOD` (33.33%). Spins wrap into [-66.67%, 0) via a GSAP modifier,
  so any number of turns is seamless. Use `spinTo` / `spinBy` from `animations/canSpin.ts`.
- `Can` takes a React 19 `ref` → `CanHandle { wrapper, label, shine }`; also `data-can`,
  `data-can-label` (+ `data-label-shift`), `data-can-shine` for selector-based animation.
  Inline label transform is first-paint only; `primeLabels()` hands it to GSAP.
- Shine (`can-shine` utility) is fixed — light source doesn't rotate, which sells the cylinder.
- Side cans reuse the same label with a hue tint — pre-render tinted WebPs (no runtime blend).
- Product cards: hover/focus = lift + one-turn spin (`animations/hoverSpin.ts`), only for
  `(hover: hover)` and no reduced motion.

## Scroll timeline

- 3 sections, each `100svh`, in normal flow. Can is a `position: fixed` layer centred in viewport.
- One ScrollTrigger over `main`: `scrub: 1`, snap to labels `hero` / `story` / `products`
  (duration 0.5–1.2s, `power2.inOut`).
- Story z-order: photo (0) < fixed can (10) < headline (20).
- **Handoff:** at step 3 the fixed can is swapped for the in-flow centre product can (same frame,
  same position), so the footer scrolls and the mobile carousel can swipe.

### Desktop (≥1024) — H = `min(61.6svh, 35.2vw)` (= 676px at 1920×1098)

| step     | rotation          | scale | x   | y       | label xPercent |
| -------- | ----------------- | ----- | --- | ------- | -------------- |
| hero     | 90°               | 1.32  | 0   | −4.8svh | −6%            |
| story    | 90°               | 2.2   | ≈0  | +2.7svh | −68%           |
| products | 0° (through ~45°) | 1     | 0   | 0       | −38%           |

Side cans in Products: medium at ±20.5vw, small at ±39.4vw, bottoms aligned; rise in with
0.08s stagger, glow fades in.

### Tablet (640–1023) — H = `min(52svh, 40vw)`

hero 90° scale 1.75 → story scale 2.05 (centred on photo) → products upright, 3 visible + swipe.

### Mobile (<640) — H = `min(42svh, 66vw)` (hero can covers ~2/3 of the headline, like desktop)

x = 0 throughout, scale 1 throughout; hero 90° → story over photo, label spins →
products upright into active carousel slot. Lenis off.

(Source of truth for H and scales is `src/styles/index.css`; positions come from the CanSlots.)

### Section content

- Hero content: yPercent −30 + fade out.
- Story headline: SplitText lines rise from yPercent 100; photo y 20svh → 0.

## Responsive

Breakpoints: mobile < 640, tablet 640–1023, desktop ≥ 1024 (scale up to 1920).

- Navbar: desktop logo/links/CTA; tablet tighter; mobile logo + hamburger → full-screen GSAP menu
  (focus trap, Esc closes, focus returns to toggle).
- Hero mobile: headline fits width, CTAs stacked full-width, socials move to footer.
- Story mobile: text on top, photo below, can over photo.
- Text sizes via `clamp()` (headline `clamp(5rem, 22vw, 26rem)`). Use `100svh`.
- Test at 375, 768, 1024, 1440, 1920 and landscape phone.

## Quality bar

- Images AVIF/WebP with `srcset`; lazy-load below the fold; preload hero can body + label.
- Lighthouse mobile: Performance ≥ 90, Accessibility ≥ 95, CLS < 0.05.
- Semantic HTML, exactly one `h1`, visible focus states, full keyboard nav.
- Product images have alt text; decorative images `alt=""`.
- `prefers-reduced-motion`: no fixed can, no pin/scrub; each section shows a static can; simple fades.
- Loader: wait for `document.fonts.ready` + can image `decode()`, then `ScrollTrigger.refresh()`.
- Hover states on buttons, nav links, product cards. Each card's glow + name use its flavour colour.
- No console errors.

## Decisions

- React 19 (user-approved; `@gsap/react` supports it).
- Display font: Sakana files will be supplied later. Until then use Exo 2 (variable, weight 800–900)
  as a placeholder — chosen because its glyph width (~0.6em) is close to Sakana's, so layout holds.
  All display text goes through `--font-display`, so swapping is a one-line change.
- Images: `vite-imagetools` for AVIF/WebP + `srcset`; `sharp` (dev) only in
  `scripts/tint-labels.mjs` to pre-render the flavour-tinted labels.
- Deploy target: undecided (Vercel or Netlify) — keep config host-agnostic until chosen.
